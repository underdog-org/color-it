# SL｜Soft Launch（W29–31）

> 上一個：[S2b](./S2b.md)｜下一個：[S3](./S3.md)｜[里程碑索引](./README.md)


**SL 驗證的是「有沒有人願意付錢」。D7 決定的是 R1 的圖庫規模、行銷投入與正式上架時點，不是「是否繼續」**——D7 在 W34 時 S3（W32–34）已經做完，而 S3 的內容（iCloud 備份、設定頁）是 P1 的落實，**無論 D7 結果如何都必須做**。

| | |
|---|---|
| **範圍** | 單一市場、**免費 6 張 ＋ 付費 12 張（共 18 張）**、零行銷預算、完整付費流程 |
| **前置依賴** | S2b、**繪師已交付並烘焙完成 ≥18 張** |

**產出物**

- 精簡版上架素材（截圖、描述、隱私標籤、分級）
- 單一市場上架（建議選英語系小市場，避免污染主市場的初期評分）
- 分析事件埋點：下載 → 首次開啟線稿 → 完成一張 → 進入付費牆 → 試用 → 轉換

**實作清單**

*上架素材*

- [ ] 精簡版商店素材：截圖（用 S2b 的版型與實際完成稿）、描述、隱私標籤、**年齡分級 4+**
- [ ] 商店分類設為 **Lifestyle / Entertainment**——**不進 Kids Category**（`prd.md §2`）
- [ ] 選定 soft launch 市場（`prd.md` A7，建議英語系小市場）

*圖庫切分*

- [ ] 免費 6 張 ＋ 付費 12 張的切分寫進 R2 目錄 JSON（S1 建立）——**必須有付費內容，全免費就量不到轉換率**

*分析埋點*

- [ ] 匿名事件埋點：下載 → 首次開啟線稿 → 完成一張 → 進入付費牆 → 試用 → 轉換
- [ ] 確認事件**不含任何可識別個人的資訊**

*送審*

- [ ] 首次送審——**同時把整條送審流程走過一遍當作預演**
- [ ] 使用者回饋收集管道（手感與內容兩類分開收）

**驗收標準**

- [ ] 送審通過（**同時完成整條送審流程的預演**，正式上架時不會有意外）
- [ ] 取得完整漏斗數據：**W31 上架起觀察至 W34，D7 在 W34**
- [ ] 取得第一批真實使用者的手感與內容回饋
- [ ] 本里程碑期間改變的決策已寫回 `prd.md` / `architecture.md` / `roadmap/`，沒有只存在於腦中的決定

> 觀察期（W31 起至 W34）與 S3（W32–34）並行——觀察數據不需要全職投入。
>
> **免費 6 張低於正式版的 8–10 張**（`prd.md §6`），因此 D7 的轉換率**只能當相對訊號，不可直接外推到正式版**——正式版免費張數更多，轉換率預期更低。
