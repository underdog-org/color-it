# M1｜資產管線（W2–3）

> 上一個：[M0](./M0.md)｜下一個：[S0](./S0.md)｜[里程碑索引](./README.md)


**它解除 E1 的輸入依賴。**

| | |
|---|---|
| **範圍** | baker CLI v1、降採樣管線、`.colorpack` 契約、三張線稿跑通全流程 |
| **前置依賴** | M0（規格文件必須先定稿；手繪素材允許跨界至 M1 期間完成） |

**產出物**

- `tools/baker` CLI：flats → connected components → region ID → **降採樣** → 膨脹 → `.colorpack`
- **三種降採樣濾波器**（flats 用 majority、lineart/shade 用 box）——見 `architecture.md §9.2`
- `contracts/colorpack.schema.json`
- baker 驗證報告格式（區域數、碎片區域、未指派像素、對齊誤差）
- 三張已烘焙的 `.colorpack`
- 程式生成的 negative fixture（刻意含縫隙的 flats、與 `flats` 不一致的 `reference`），置於 `tools/baker/tests/fixtures/`

**實作清單**

*baker 核心*

- [ ] baker CLI 骨架：clap 參數、輸入目錄結構解析、輸出路徑
- [ ] `meta.json` 讀取與驗證：`id` 與資料夾名一致、`category` 為已知值（未知值拒收）
- [ ] 母帶前置驗證：四張圖尺寸與對齊一致、長邊 4096、比例為 1:1 或 4:5
- [ ] **色彩空間驗證**：讀 PNG 的 `iCCP` / `sRGB` chunk，帶 Display P3 描述檔一律拒收
- [ ] `flats` 掃描唯一 RGB → connected components → region ID（含抗鋸齒偵測：顏色數超出合理範圍即拒收）
- [ ] 母帶「**無未指派像素**」驗證（無例外，含線稿覆蓋處）
- [ ] `reference` 與 `flats` 的區域邊界一致性驗證 ＋ **每個區域內顏色唯一**驗證
- [ ] `lineart` / `shade` 合成到白底——**必須在降採樣之前**（`architecture.md §9.2` 陷阱 0）
- [ ] 三種降採樣濾波器：`flats` = 2×2 majority、`lineart` / `shade` = box
- [ ] 區域向線稿下方膨脹 2px——**必須在降採樣之後**（陷阱 2）
- [ ] 輸出解析度後置驗證：區域數與母帶一致（不一致＝有區域被吃掉，錯誤）、碎片區域 < 200px（警告並列座標）、`region_count ≤ 65535`（錯誤）
- [ ] `reference.png` 逐區讀建議色 → `palette[]`（在母帶解析度讀，`reference` 不降採樣、不進 pack）
- [ ] 難度分級計算：`region_count` **≤60 輕鬆｜61–200 適中｜>200 專注**——SSOT 在 `specs/assets-spec.md`（給繪師的文件），`architecture.md §9.4` 與本條皆為引用，**改門檻必須三處同動**
- [ ] `.colorpack` 打包：`manifest.json` / `lineart.png` / `shade.png` / `regions.bin`（R16 RLE 無損）/ `regions.json` / `thumb.jpg`
- [ ] 驗證報告輸出（區域數、碎片區域座標、未指派像素、對齊誤差）

*契約與測試*

- [ ] `contracts/colorpack.schema.json` ＋ Rust 端驗證；`manifest.schema_version` **從第一天存在**，runtime 拒絕未知 major
- [ ] negative fixture 生成器：含縫隙的 `flats`、與 `flats` 不一致的 `reference`、帶 Display P3 描述檔的圖、開了抗鋸齒的 `flats`
- [ ] baker 拒收測試進 CI——**每個 negative fixture 對應一條測試**，且失敗訊息必須含座標
- [ ] `cargo xtask bake <dir>` 接上 baker
- [ ] CI：`assets/source/**` 變更時自動跑烘焙驗證（含輸出解析度的後置驗證）

*外部前置*

- [ ] **繪師人選確認（W3–5）**——D1 的前置（徵才已於 M0 的 W1 發出，lead time 2–4 週）
- [ ] **採購一台低階 Android 裝置**（E1 的 D2 spike 需要，見 [checkpoints.md](./checkpoints.md) 外部前置）

**驗收標準**

- [ ] 三張圖皆能產出 `.colorpack`，無未指派像素
- [ ] 區域數與預期一致（人工核對）
- [ ] 刻意放入有縫隙的 flats，baker 必須**拒收**並指出座標
- [ ] `reference` 與 `flats` 區域邊界不一致時，baker 必須**拒收**
- [ ] **降採樣後（2048 / 1920 輸出解析度）重跑全部驗證仍通過**——碎片區域檢查必須在輸出解析度判定
- [ ] 1:1 與 4:5 兩種比例各跑通一張
- [ ] `has_shade` 為 true / false 兩條路徑皆跑通
- [ ] 本里程碑期間改變的決策已寫回 `prd.md` / `architecture.md` / `roadmap/`，沒有只存在於腦中的決定

> **⚠️ D1 不在 M0 / M1 驗收內。** 原本的最後一條「繪師依規格獨立完成一張交付，無需來回澄清」已移出——這期間素材由工程自製，而**自己交付得出來不代表外人交付得出來**：你手上有全部脈絡，這條在自製情境下驗證不了。它移到繪師首次獨立交付時，見 [checkpoints.md](./checkpoints.md) D1。
>
> M0 驗收裡的「交給未參與者閱讀」是這條的**預演**，能提早發現規格文件的表達問題，但它驗證的是讀得懂，不是做得出來。
>
> 這件事必須明確記錄，否則 roadmap 上最重的一個煞車會靜靜消失。
