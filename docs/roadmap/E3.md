**產出物**

- `core/history`：`UndoEntry` 雙型別（PaintTiles / Fill）＋ **undo pool 記憶體上限**
- `core/oplog` ＋ `contracts/oplog.schema.json`
  - **量化後的 sample**（座標 int16、時間 delta、壓力 u8），不存 raw sample
  - **磁碟上只含有效 op**——undo 表現為尾巴截短，不寫 Undo/Redo marker
- **`Document::apply` 單一寫入口**（Boundary 5）
- 本機存檔 ＋ 雲端備份兩套格式（`architecture.md §8.2`）
- Keyframe 策略、自動存檔、**atomic rename 的截短寫入**
- **非同步 readback 基礎設施**（ring buffer ＋ fence）——undo 提交與進度計算共用
- **進度計算 compute pass**（per-region 覆蓋率，節流 500ms）
- 縮時影片匯出（MP4）

**實作清單**

*非同步 readback 基礎設施（先做，另外兩件事都依賴它）*

- [ ] ring buffer ＋ fence 的非同步 readback——**undo 提交與進度計算共用同一套**（`architecture.md §4.7`、§14 R6）
- [ ] `TileSnapshotProvider` trait：**`document` 定義、`render` 實作**，以依賴反轉保持依賴方向向下（`architecture.md §5.1`）
  - 這裡若沒有明確規則，一定會被隨手打破成「`engine` 從 `render` 拿 blob 再塞給 `history`」

*Undo*

- [ ] `core/history`：`UndoEntry` 雙型別——`PaintTiles { tile_ids, blob }` 與 `Fill { region, old, new }`（後者 8 bytes）
- [ ] tile COW：dirty tile **同時快照 `T_paint` ＋ `T_erase`**（R8 讓 undo 體積 +25%）
- [ ] undo pool **64MB 上限**，超過丟棄最舊 entry——**undo 深度是動態的**，不是固定步數

*OpLog*

- [ ] `core/oplog` ＋ `Op` enum：`BeginStroke` / `StrokeSamples` / `EndStroke` / `Fill` / `EraseStroke`
  - **沒有 `Undo` / `Redo` op**，且已移除的 `EraseRegion` 識別碼**不得回收**
- [ ] `QuantizedSample` 量化（x/y `i16`、dt `u8`、pressure `u8`、radius `u8`、tilt `i8`×2）＋ 座標 delta 編碼
- [ ] **磁碟只含有效 op**：undo 表現為有效長度縮短；undo 後畫新筆畫直接覆寫被截短的尾巴
- [ ] `contracts/oplog.schema.json` ＋ 向前相容規則：**遇到未知 op 型別以唯讀模式開啟並提示升級，不得靜默略過**

*持久化*

- [ ] **`Document::apply` 單一寫入口**（Boundary 5）——任何狀態變更都必須先成為一個 `Op`
- [ ] 本機存檔 `document.bin`：header / palette / `paint_tiles`（QOI 或 PNG 無損）/ 完整 oplog
- [ ] 雲端備份 `backup.bin`：header / palette / 量化壓縮 oplog / thumbnail——**不含 raster**
- [ ] Keyframe 策略（每 N 個 op 或每 30 秒）＋ 自動存檔
- [ ] **atomic rename 寫入**：寫 `.tmp` → `fsync` → rename，**不得就地截斷**
- [ ] **undo 之後觸發一次寫檔**，否則「undo 三步 → 崩潰 → 重啟」會讓那三步復活
- [ ] 備份配額降級策略：接近上限時丟棄最舊且已分享作品的 oplog，**任何情況下不刪本機文件**

*進度*

- [ ] 進度計算 compute pass：per-region `atomicAdd` 覆蓋率，**只跑 dirty tile 增量累加**，抬筆後節流 500ms
- [ ] 「已上色」判定：油漆桶填過 **或** 該區筆刷覆蓋率 > 50%；完成建議觸發條件為**全區已上色且距上一筆 > 3 秒**

*縮時*

- [ ] oplog 重播渲染 → 影格序列（`seed` 固定確保與原作一致）
- [ ] MP4 編碼與匯出

*外部前置*

- [ ] **W20 啟動 App Store Connect 帳務設定**（稅務、銀行資訊、訂閱產品建立、審查）——lead time 數週且不可預測，見 [checkpoints.md](./checkpoints.md) 外部前置

**驗收標準**

- [ ] 連續 100 次 undo/redo 後畫面與初始狀態逐像素一致
- [ ] 強制終止 App 後重啟，復原至最後一筆；**進行中未 commit 的筆畫被正確丟棄**
- [ ] undo 後立即強制終止 App，重啟後被 undo 的筆畫**不會復活**
- [ ] **靜態分析或 code review 確認：沒有任何繞過 `apply` 的狀態變更路徑**
- [ ] 備份格式在只用油漆桶的作品上，還原後 100% 精確
- [ ] **重度筆刷作品（連續塗抹 30 分鐘）的 oplog 壓縮後體積實測**，並記錄還原重播耗時
- [ ] 進度計算：只用筆刷的作品進度會正確前進；單點一下不會讓區域被判定為已上色
- [ ] 縮時影片可匯出、時長合理，且**不包含被 undo 掉的筆畫**
- [ ] Undo 提交不造成可感知的頓挫（見 `architecture.md §14 R6`）
