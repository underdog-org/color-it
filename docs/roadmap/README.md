## 前提

**所有週數都建立在以下配置上。配置改變，整份時程作廢。**

| 項目 | 假設 |
|---|---|
| 工程 | **1 人全職** |
| 繪師 | 外包，1 位，穩態產能每週 3–5 張 |
| 繪師預算 | v1 上架前 50 張 × $80 ≈ **$4,000**，這是唯一的現金支出 |
| v1 平台 | **iOS only**。Android 移出 v1，見 [beyond-v1.md](./beyond-v1.md) |
| 上架形式 | 先 soft launch（單一市場），再正式上架 |

**這個配置的直接後果**：工程是關鍵路徑（約 38 週），繪師不是——低速 9 張 ＋ 量產 41 張 ÷ 每週 3.5 張 ≈ 12 週，**W16–27 即可達 50 張**，而 D8 在 W34，繪師軌有約 8 週 buffer。這與 v0.1 的假設完全相反，v0.1 的「三軌並行」在單人配置下不成立。

## 里程碑

每個里程碑一份檔案，三段結構：`產出物`（交什麼）→ `實作清單`（做什麼，每條 1–3 天）→ `驗收標準`（怎麼算完成）。

| 里程碑 | 週次 | 內容 | 檔案 |
|---|---|---|---|
| **M0** | W0–1 | 專案基建、繪師交付規格、三張試作素材 | [M0.md](./M0.md) |
| **M1** | W2–3 | baker、`.colorpack` 契約、驗證測試 | [M1.md](./M1.md) |
| **S0** | W4 | 契約定義（`EngineProtocol` ＋ `MockEngine` ＋ Xcode 專案） | [S0.md](./S0.md) |
| **E1** | W5–10 | 手感垂直切片 ★ 最高風險（時間盒 8 週） | [E1.md](./E1.md) |
| **E2** | W11–14 | 完整工具集（五支筆刷、橡皮擦、縮放平移） | [E2.md](./E2.md) |
| **S1** | W15–19 | Gallery ＋ Canvas Shell ＋ **資產分發（R2）** | [S1.md](./S1.md) |
| **E3** | W20–24 | Undo ＋ OpLog ＋ 持久化 ＋ 進度 | [E3.md](./E3.md) |
| **S2** | W25–27 | Share ＋ Subscription ＋ **解鎖 Worker** ＋ **完成建議與完成動畫** | [S2.md](./S2.md) |
| **S2b** | W28 | 品牌與 Logo ＋ 商店截圖版型 ＋ 手動匯出／匯入 | [S2b.md](./S2b.md) |
| **SL** | W29–31 | Soft Launch（觀察期至 W34，與 S3 並行） | [SL.md](./SL.md) |
| **S3** | W32–34 | 雲端備份（iCloud、設定頁、`asset_hash` 降級） | [S3.md](./S3.md) |
| **R1** | W35–38 | 正式上架 | [R1.md](./R1.md) |

※ M0 / M1 的 3 張試作由工程自製，不依賴繪師。

```
工程軌  ▓▓▒▒ █ ██████ ████ █████ █████ ███ ▒ ███ ██ ███████

        對齊  交付            （約 W27 達 50 張）
              ▲D1            ▲ W16 起（E1 完成後）
```

```
M0 ──▶ M1 ──▶ E1 ──▶ E2 ──▶ S1 ──▶ E3 ──▶ S2 ──▶ S2b ──▶ SL ──┬──▶ R1
        │      ▲                                                │
        │      │                                           S3 ──┘

繪師：規格對齊(W0–1) ── 徵才(W1 發出) ── 首次交付 D1(W5–7) ── 低速(W7–15) ── 量產(W16–27) ──▶ R1
```

`S0` 沒有前置依賴，排在 W4 只是因為 M0/M1 佔住了 W0–3。**E1 卡關時可以往前抽 S1 來做**（Mock 已就緒），不要空轉。
