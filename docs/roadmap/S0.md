> S0 的最大不確定性是**首次**把 Rust 經 uniffi 產出 `.xcframework` 並在 Xcode 連起來。若這件事吃掉超過 3 天，優先把 `MockEngine` 與五條路由空殼做完（S1 的前置），uniffi 打通可以壓到 W5 初與 E1 重疊。

> 接手 iOS 骨架時要知道的兩件事（都已在 S0 解掉，理由見 `specs/ffi-contract.md §6`）：
>
> - Rust 的 Object 叫 **`RustEngine`**，所以 uniffi 生的是 `RustEngine` ＋ `RustEngineProtocol`。
>   手寫的 `EngineProtocol.swift` 不會撞名——但**不要**把 Object 改回 `Engine`，那會變成
>   同一個 module 裡的 invalid redeclaration。
> - modulemap 是 `module`（非 `framework module`）。實測 `framework module` 會讓生成的 Swift
>   出 220 個 error 而 `xtask ios` 照樣 exit 0，所以 `xcframework` 旗標固定為 `false`。
>
> 兩者都只有 Swift 編譯器抓得到，CI 的 macOS gate 不編 Swift。**接 Xcode 時第一件事是編一次。**
