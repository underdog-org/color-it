# S0｜契約定義（W4）

**產出物**

- `core/engine` facade 骨架 ＋ uniffi UDL（**v1 只生成 Swift**）
- Xcode 專案 ＋ `EngineBridge` 獨立 framework target
- `apps/ios/EngineBridge/EngineProtocol.swift` ＋ `MockEngine.swift`
- `Tool` / `InputSample` / `UiState` 的初版型別定義
  - `InputSample` **必須包含 `radius: f32`**——手指的接觸半徑，見 `architecture.md §10.2`
- `cargo xtask ios` ＋ `verify-generated`
- `docs/contracts.md` 首版
- **標記為 `v0`，明確預告會在 E2 / E3 各有一次修正**

**實作清單**

*Rust 契約*

- [ ] `core/engine` facade 骨架 ＋ uniffi UDL（v1 只生成 Swift）
- [ ] `Tool` / `InputSample` / `UiState` 型別定義——`InputSample` **必須含 `radius: f32`**
- [ ] FFI 表面依 `architecture.md` Boundary 1 定義：`append_samples` 走批次，**不得出現 per-touch 的 FFI call**
- [ ] `cargo xtask ios`：產生 `.xcframework` ＋ Swift binding → `apps/ios/Generated/`
- [ ] `docs/contracts.md` 首版：FFI semver 規則與 major bump 的遷移記錄格式（`architecture.md §7`）

*iOS 骨架*

- [ ] 建立 Xcode 專案 `apps/ios/ColorApp`，**五條路由**的空殼導航（Gallery / Canvas / Share / Subscription / Settings）
- [ ] `EngineBridge` 拉成**獨立 framework target**，不散落在 App code 裡（`architecture.md §10.1`）
- [ ] `EngineProtocol.swift`：介面定義，檔頭標記 `v0` 並註明 E2 / E3 各有一次預期修正
- [ ] `MockEngine.swift`：靜態圖畫布、`tap()` 假裝改變 progress 並照常發送 `state`、其餘 no-op
- [ ] `MockEngine` 用的靜態範例圖（直接用 M0 的手繪素材）

*CI*

- [ ] `verify-generated` 進 CI：binding 過期時失敗
- [ ] `apps/ios/Generated/` 進 `.gitignore`，CI 每次重建

**驗收標準**

- [ ] 以 Mock 啟動一個顯示靜態圖的畫布
- [ ] `tap()` 能驅動 progress 變化並反映到 UI
- [ ] `verify-generated` 在 binding 過期時確實失敗
- [ ] **五條路由**的空殼可完整導航（Gallery ⇄ Canvas → Share；Gallery → Subscription；Gallery → Settings）
- [ ] **App Shell 端沒有任何一行直接引用 `RustEngine`**——只依賴 `EngineProtocol`
- [ ] `EngineProtocol.swift` 與 Rust FFI 表面逐一對照無缺漏——特別是 `cancelStroke` / `render` / `setViewport` / `save` / `exportTimelapse`（`architecture.md §10.1` 目前列的介面比 §6 的 FFI 少五個）
- [ ] 本里程碑期間改變的決策已寫回 `prd.md` / `architecture.md` / `roadmap/`，沒有只存在於腦中的決定

> S0 的最大不確定性是**首次**把 Rust 經 uniffi 產出 `.xcframework` 並在 Xcode 連起來。若這件事吃掉超過 3 天，優先把 `MockEngine` 與五條路由空殼做完（S1 的前置），uniffi 打通可以壓到 W5 初與 E1 重疊。
