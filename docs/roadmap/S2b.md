# S2b｜品牌與 SL 前置整備（W28）

> 上一個：[S2](./S2.md)｜下一個：[SL](./SL.md)｜[里程碑索引](./README.md)


> **為什麼獨立成 1 週**：這兩塊都是「排在別人後面就會被犧牲」的工作。
>
> **品牌是已知會被壓縮的高風險項**——`strategy.md` 的風險表已經承認「設計與品牌由工程自己做」是本專案的特有風險。把它留在 S2 那個已經有 Share、StoreKit、Worker 三塊硬工作的里程碑，等於保證它是被壓縮的那一塊；而 D7 若轉換率偏低，臨時素材會讓結果有兩種無法區分的解釋（產品不吸引人 vs 商店頁太隨便），D7 的整個價值就在於區分它們。
>
> **手動匯出必須趕在 SL 之前**——SL 是真的上架收費。若備份要等到 S3，soft launch 期間換機、刪 App、iCloud 未登入的使用者，作品就是消失。`prd.md §3` 的 P1 是最高原則，不能在首次真實上架時缺席。走 iCloud Drive 的邊際成本近乎零，成本只有一個分享面板入口。

*品牌*

- [ ] **App Logo 與 App Icon**
- [ ] 品牌基礎：主色、字體（**名稱與商標可用性已在 M0 確認**，`prd.md` A1）

- [ ] 匯出作品檔到系統「檔案」App（**走 iCloud Drive，此處主要是加分享面板入口**）

**驗收標準**

- [ ] Logo 在深色／淺色背景、各尺寸下皆可辨識
- [ ] 商店截圖版型用的是**實際完成稿**，不是 UI 截圖
- [ ] **手動匯出的檔案能在另一台裝置匯入並正確開啟**——SL 上架前 P1 的逃生口已就位
- [ ] 本里程碑期間改變的決策已寫回 `prd.md` / `architecture.md` / `roadmap/`，沒有只存在於腦中的決定
