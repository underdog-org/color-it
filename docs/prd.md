## 1. 產品定位

**Colorlull 是一款以高品質線稿為核心的著色 App，讓不會畫畫的人也能做出有創作感的作品。**

功能光譜的一端是純填色遊戲（點擊上色，門檻極低但沒有創作感），另一端是專業繪圖軟體（表現力強但門檻高）。Colorlull 站在中間——**用填色的門檻，換創作的成就感**。

| | Happy Color 類 | 專業繪圖類 | **Colorlull** |
|---|---|---|---|
| 核心動作 | 點擊填色 | 自由繪畫 | **點擊填色 ＋ 自由塗抹並存** |
| 筆刷 | 無 | 數十至數百支 | **5 支，經過挑選** |
| 上手門檻 | 極低 | 高 | **低** |
| 主要感受 | 完成感 | 創作感 | **兩者兼具** |
| 一張圖耗時 | 10–30 分鐘 | 數小時 | **15–45 分鐘** |

### 差異化不在功能，在素材

**上表描述的是產品形態，不是護城河。**

「填色 ＋ 筆刷 ＋ 訂閱制」的中間地帶並非空白——Pigment、Recolor、Lake 等產品已在此位置。**不要把功能組合當成差異化來論證。**

真正的差異化是兩件事：

1. **素材的風格識別度**——線稿本身的美術方向是否有一致的、可辨認的品味，而不是通用素材庫的堆疊
2. **完成稿的精緻程度**——同樣的使用者操作，我們的成品要明顯更好看。這由三件事共同決定：線稿品質、`flats` 帶來的零漏色、`shade` 層讓成品有立體感

**這個差異化的商業風險**：它在商店頁的截圖上**看得出來**（成品圖），但在功能列表上看不出來。因此：

- 商店截圖必須是**實際完成稿**，不是 UI 截圖
- 縮時影片是唯一能在商店外傳達品質的載體，這是它必須進 v1 的原因（見 §9）

> 定價、獲客與 breakeven 的假設見 §7。

### 為什麼兩種模式必須並存

- **油漆桶提供「完成感」**——低門檻、即時回饋、可以在通勤時完成一張。這是**獲取與早期留存**的來源．類似於Happy Color的體驗。
- **筆刷提供「創作感」**——同一張線稿，不同人塗出不同結果。這是**長期留存與付費意願**的來源，類似於Lake的做法。

只做前者會變成又一個填色遊戲；只做後者會流失掉大部分不敢下筆的使用者。

### 我想解決的問題

> 有沒有一款App，就算我沒有美術基礎，也可以讓我真的畫出像是網路上看到的精美的創作

- 填色遊戲 (Happy Color)的痛點：
  - 填色區域太多、太複雜，對於兒童的門檻很高
  - 有非常多的廣告，打斷心流體驗
  - 真正的核心體驗類似於「找找看」，而非是繪圖App
- 筆刷＋著色遊戲（Lake）的痛點：
  - 大多素材的風格都是屬於風景、可愛、曼陀羅
  - 我想填補市場空白——「動漫風格」「兒童風格」與「IP聯名合作」，吸引不同的族群
  - 學習曲線較高，需要熟悉筆刷的操作

### 可以學習的方向

- 填色遊戲：
  - 豐富的線稿選擇
  - 極簡的操作與0上手成本
- 筆刷+著色遊戲：
  - 簡化傳統繪圖軟體(Procreate, Clip Studio Paint)的介面與工具，更適合非專業使用者使用
  - 封閉區域的填色體驗極佳
  - 自由切換是否要開啟「線稿」模式

## 2. 目標用戶

### 主要（設計以此為準）

- **25–45 歲成人**，使用情境為紓壓、喜歡動漫、可愛、風景風格、睡前放鬆、通勤空檔
- **全球市場**，英語為第一語言。v1 上**英文、繁體中文、日文**；德語與西語列 v1 之後
  - 繁中的理由是**團隊母語，便於驗證 i18n 結構**，不是市場策略
  - 日文的理由是市場——著色 App 在日本市場強勢，且與「動漫風格」的素材定位一致
- 主要裝置為**手機**，平板為輔
- 主要輸入為**手指**，觸控筆為輔

**關於「手指沒有壓感」——這是產品約束，不是實作細節。**

主要使用情境下 `pressure` 是常數，因此五支筆刷的差異**不能依賴壓感曲線**，必須由筆尖紋理、間距、混合模式與 build-up 撐起。動態的替代來源是**接觸半徑**（`UITouch.majorRadius`，壓得越用力接觸面積越大）與**速度**。

因此凡是筆刷相關的驗收，**一律以手指為準**——用觸控筆測會得到假的通過。詳見 `architecture.md §10.2`。

### 次要

- **兒童可以使用，但產品不為兒童設計。**

這個區別很重要：兒童不是主要使用者，也不是付費族群。因此我們**不宣稱面向兒童**，也不進入 App Store 的 Kids Category——那會帶來一整套針對兒童導向 App 的分析與外部連結限制，換不到對應的商業回報。

| 決策 | 內容 |
|---|---|
| 年齡分級 | 4+ |
| 商店分類 | Lifestyle / Entertainment（**不進 Kids Category**） |
| 分析 | 匿名事件。因不宣稱面向兒童，第三方分析 SDK 可用，但仍不收集任何可識別個人的資訊 |

即使不進 Kids Category，以下三條仍然保留——它們本身就是好設計，不只是合規要求：

1. 不做社群功能、不做使用者間互動
2. App 內不放外部連結（付費流程除外）
3. 線稿內容維持全年齡分級

## 3. 核心原則

以下四條原則的優先序高於任何個別功能需求。當需求與原則衝突時，砍需求。

### P1 — 作品不可「消失」★

使用者投入 30 分鐘完成的作品，是他的東西，不是我們的。

**a. 已編輯的作品，不因商業狀態改變而失效**

- 線稿從圖庫下架 → 已開始編輯的作品仍可開啟、繼續編輯、匯出、分享
- 訂閱到期或取消 → 已開始編輯的作品仍可開啟、繼續編輯、匯出、分享
- 訂閱到期後**唯一受限的是「開啟新的付費線稿」**，不影響任何既有作品

**b. 版本更新不破壞既有作品**

- 任何 App 版本更新後，過去所有版本產生的作品都必須能正常開啟與編輯
- 線稿如果重新製作（修正縫隙、調整區域），舊版本必須繼續存在，既有作品繼續指向舊版本
- 存檔格式只能向前相容地演進，不得出現「舊檔無法開啟」的版本

> 這條原則在技術上的落實方式見 `architecture.md §8 狀態與持久化`、`§9 資產管線`。
> 它是幾個架構決策的唯一理由：資產不可變、內容雜湊、schema 版本化、已觸碰資產永久釘選。

### P2 — 手感優先於功能數量

寧可 5 支筆刷都好用，不要 30 支筆刷有 25 支沒人用。任何新功能提案，先問「它會不會拖慢下筆到出墨的延遲」。
由於主要客群非專業用戶，減少工具的選擇可以降低學習門檻與心智負荷。

### P3 — 不讓使用者做決定

使用者打開 App 是為了放鬆、快速使用與繪畫，不是為了設定參數。預設值就是好值。設定頁應該只有寥寥數項。

### P4 — 不需要帳號（後端）

不註冊、不登入、不要 email，降低註冊與登入的摩擦力，讓App可以開箱即用，使用者的資料在他自己的裝置與他自己的雲端空間裡。

## 4. 核心體驗

### 4.1 三個工具

| 工具 | 產品語意 | 遮罩模式 |
|---|---|---|
| **油漆桶** | 點一下，整個區域瞬間填滿 | **嚴格**——只影響點到的那個封閉區域 |
| **筆刷** | 自由塗抹，但塗不出線稿之外 | **寬鬆**——可跨區塗抹，但線稿本身永遠不會被蓋住 |
| **橡皮擦** | **擦掉覆蓋到的顏色**（含油漆桶填的底色） | 與筆刷相同（寬鬆，且固定不可切換） |

**兩種遮罩模式的體驗差異，是本產品最重要的單一設計決策。**

- 油漆桶用嚴格模式，因為它的價值是「不用瞄準」——手指再粗都不會塗出界，這是低門檻的來源。
- 筆刷用寬鬆模式，因為它的價值是「隨性」——可以一筆掃過三個區域做漸層，不用切換選取。線稿本身不會被蓋住，所以再怎麼亂塗，成品都不會醜。

> 這兩種模式在 shader 層只差一個判斷式，實作成本相同，但體驗差異巨大。實作見 `architecture.md §4.4`。

**橡皮擦的語意（重要）**

橡皮擦的行為是「**只擦掉自己筆刷覆蓋到的面積**」，就像它也是一支筆刷——不論底下是筆刷塗抹還是油漆桶底色，覆蓋到的部分都回到未上色。

這件事在技術上不是免費的：油漆桶的顏色不在 raster 裡，而是「一個區域一個值」，所以「局部擦掉底色」需要額外一張逐像素的擦除遮罩。實作與代價見 `architecture.md §4.1 / §4.2`。

之所以值得付這個代價：使用者對橡皮擦的預期是「擦掉我看到的顏色」。若橡皮擦擦不掉油漆桶的填色，在使用者眼裡不是設計取捨，就是 bug——而且是每天都會撞到的那種。

**橡皮擦固定使用寬鬆模式，不提供模式選擇**。使用者拿橡皮擦時是在修正錯誤，這是最不希望被區域邊界卡住的時刻；而「線稿不會被擦掉」已經提供了足夠的無害性。

**未上色 = 白色**

畫布底色固定為白色（著色書的紙），擦除後露出的是白色而非透明。匯出的 PNG 同樣是白底——透明背景在社群平台上會顯示為棋盤格。「透明背景匯出」列為 v1 之後。

> **⚠️ 待決策｜「封閉線稿」開關**
>
> 目前另有一個提案：仿 Lake，讓使用者自由切換「封閉線稿」是否開啟（開啟＝繪圖受封閉區域限制，關閉＝整張畫布視為一個區域）。
>
> 它與本節的設計**直接衝突**，需要擇一：
>
> - 本節的設計是 **mask mode 綁在工具上**（油漆桶嚴格、筆刷寬鬆），使用者不需要知道 mask 的存在
> - 開關的設計是 **mask mode 是全域使用者設定**，且「關閉」會讓筆刷可以蓋住線稿——成品有可能變醜
> - 全域開關同時牴觸 P3（不讓使用者做決定）
>
> 建議在 **D4**（E1 結束，Mask Mode A/B 實機比較時）一併拍板。在那之前，實作以本節的「綁在工具上」為準。

### 4.2 油漆桶的體驗細節

點擊 → 顏色從點擊處**擴散**填滿整個區域（而非直接填滿） → 輕微觸覺回饋。

擴散動畫不是裝飾，它是這個 App 的核心爽點，決定使用者願不願意點第 50 下。動畫時長需要實機調校（初始值 180ms，ease-out）——太快沒有滿足感，太慢會阻礙連續操作。

### 4.3 五支筆刷的產品定位

| 筆刷 | 使用者會拿來做什麼 |
|---|---|
| **軟圓筆** | 基礎款。柔和邊緣，適合大面積鋪色與漸層 |
| **麥克筆** | 疊色會變深。適合刻意加重、畫出層次 |
| **蠟筆** | 帶顆粒紋理。適合做出手繪的粗糙質感 |
| **噴槍** | 慢慢堆疊出濃度。適合柔和的光暈與陰影 |
| **水彩** | 邊緣會暈染加深。適合植物、天空這類有機主題 |

五支筆刷在技術上共用同一條渲染路徑，差別只在參數。**產品上要確保它們的差異一眼可辨**——如果使用者切換筆刷後看不出差別，那支筆刷就該砍掉或重調。

### 4.4 顏色

- 每張線稿附帶一組**建議調色盤**（繪師交付一張 `reference.png` 建議配色稿，由 baker 逐區讀取。見 `architecture.md §9.1`）
- 建議調色盤是預設值，但使用者可以自由取用完整色盤
- 使用者塗過的顏色進入「最近使用」
- **吸管**是 Canvas 色盤的取色入口之一，讓使用者直接從畫布上取用已塗的顏色。建議調色盤仍是預設與主要路徑——吸管是補充，不是替代（降低著色門檻）

### 5.1 Gallery — 選擇作品

**兩個分頁**：

| 分頁 | 內容 |
|---|---|
| **探索** | 全部線稿，依分類瀏覽。每張顯示縮圖、難度、鎖定狀態 |
| **我的作品** | 已開始編輯的作品，依最後編輯時間排序，顯示完成進度 |

**每張線稿卡片的狀態維度**：

| 維度 | 值 |
|---|---|
| 下載 | 未下載 / 下載中 / 已下載 |
| 鎖定 | 免費 / 已解鎖 / 鎖定（鎖定的仍可預覽縮圖） |
| 進度 | 未開始 / 進行中（顯示進度環）/ **已分享** |

**「已分享」而不是「已完成」**

第三個維度刻意用「有沒有匯出過」這個**客觀事實**，而不是用「填了多少」這個推測值。

理由有三：

1. **零誤判**。完成建議的判定必然有偽陽性風險，但「使用者按過分享」是確定的
2. **對留存的訊號更有用**。真正想知道的是有多少作品被分享出去——那是自然傳播的直接指標
3. **不強加創作觀**。有人會刻意留白（負空間也是構圖），用「所有區域都上色」定義完成，等於說他們沒畫完

進度環仍然顯示覆蓋率，它負責「我進行到哪」；「已分享」負責「這張我結束了」。

**鎖定規則（一條規則取代狀態組合表）**

> **一旦某個 `asset_id` 有對應的本機文件，該 asset 在所有 UI 上都不再顯示鎖定** —— 包含探索分頁，那裡改為顯示「繼續」。

這條規則讓 P1-a 在 UI 層變成一個可驗證的不變式，而不是散落各處的 if 判斷。它同時消滅了「鎖定 × 進行中」這個原本無法定義的狀態組合——因為它不可能出現。

**不可能的狀態組合**（實作時應以斷言排除，而非畫出 UI）：

| 組合 | 為什麼不可能 |
|---|---|
| 未下載 × 進行中 | 已開始編輯的資產永久釘選，有文件必有資產（`architecture.md §8.5`） |
| 鎖定 × 進行中 | 上面那條規則 |
| 鎖定 × 已分享 | 同上 |

**難度分級**：由 baker 依區域數自動計算，分成三級（輕鬆 / 適中 / 專注）。不用數字，用感受性的詞。

> baker 的難度計算屬 v1 Must Have（資料要在 `.colorpack` 裡）；Gallery 的**難度篩選 UI** 屬 Should Have。見 §9。

### 5.2 Canvas — 畫布

**畫面元素**：

- 畫布（可雙指縮放、平移）
- 工具列：筆刷 / 橡皮擦 / 油漆桶 ＋ 筆刷大小＆透明度
- 色盤：建議色（作為引導） ＋ 最近使用 ＋ 完整色盤入口 ＋ 吸管
- Undo / Redo
- 返回、分享入口

**筆刷大小與透明度（不是「筆刷參數編輯」）**

透明度是**「整筆上限」的使用者覆寫**，預設值來自筆刷本身的 preset（`architecture.md §4.6` 的 `BrushPreset.opacity`）。使用者調的是單一數值，不是一組參數——這與 Don't Have 的「使用者自訂筆刷參數」是兩件事（見 §9）。

**橡皮擦與筆刷共用同一個大小值**，不分開設定。理由是 P3：少一個要做的決定。

**關鍵行為**：

- **自動存檔**——沒有「儲存」按鈕。任何時候關掉 App 都不會丟失
  - 但 **Undo 歷史不跨 session 保留**。關掉 App 再打開，作品狀態完整，但不能再撤銷上次的操作。理由見 `architecture.md §6 Boundary 6`
- **完成建議（原「完成偵測」）**——見下方
- **不打擾**——編輯過程中不彈任何東西（付費牆、評分請求、推播授權），全部延後

**完成建議的設計**

誤判的成本高度不對稱：

| 方向 | 後果 |
|---|---|
| **偽陽性**（沒畫完就說完成） | **嚴重**——在使用者最投入時打斷創作，直接違反「不打擾」 |
| 偽陰性（畫完了沒觸發） | 溫和——使用者自己按分享，零功能損失 |

**因此完成建議的判定極度保守，寧可漏判。**

- **進度定義**：已上色的區域數 ÷ 總區域數。「已上色」＝ 該區域被油漆桶填過，**或**該區域內筆刷覆蓋率 > 50%
  - 50% 這個門檻解決了「只點一下就算整區完成」的問題
- **觸發條件**：所有區域皆已上色 **且** 距離上一筆超過 3 秒（避免在連續操作中途打斷）
- **文案是建議不是判定**：「看起來不錯了，要分享嗎？」，而不是「完成！」
- **永遠不是必經路徑**：工具列上一直有分享入口，漏判零損失
- **完成動畫的定義**：進度環填滿的短動畫 ＋ 建議文案同時出現。**不阻斷、不強制關閉**——使用者可以無視它直接繼續畫。「建議」是判定與文案，「動畫」是它的視覺呈現，兩者一起觸發

**已知並接受的取捨**：刻意留白創作的使用者不會觸發完成建議，也就看不到完成動畫。這是保守策略的必然代價，而且比誤判打斷創作好得多。

> 進度計算的技術實作見 `architecture.md §4.7`。

### 5.3 Share — 分享與匯出

| 產出 | 說明 |
|---|---|
| **靜態圖片** | PNG，白底，含線稿與陰影合成 |
| **縮時影片** | 由操作紀錄重播錄製，MP4。**這是主要的自然傳播來源，v1 Must Have** |

**匯出比例**

線稿資產只有兩種比例（1:1 與 4:5，見 §6），但社群平台的目標比例不只兩種。因此匯出時做 **letterbox**：畫布置中，背景延伸填滿目標比例。

| 目標 | 比例 |
|---|---|
| Instagram feed、通用 | 1:1 |
| Instagram 直式 feed | 4:5 |
| **Stories / Reels / TikTok / Shorts** | **9:16** ← 縮時影片的主要目標 |

匯出後導向系統分享面板。不做站內社群。

**縮時影片為什麼是 Must Have**：§1 已經說明，本產品的差異化（素材風格、完成稿精緻度）在功能列表上看不出來，只能靠成品傳達。縮時影片是唯一能在商店頁之外傳達品質的載體。它的邊際成本也最低——操作紀錄（oplog）為了備份本來就必須存在。

### 5.4 Subscription — 付費牆

**三個進入點**：

1. 點擊鎖定的線稿
2. Gallery 的訂閱入口
3. **已分享** N 張作品之後（正向時機，不阻斷）

用「已分享」而不是「完成」：與 §5.1 Gallery 第三維度用的是同一個客觀事實，且它比「觸發完成建議 N 次」保守，較不會打擾。N 值待上線後校準（附錄 A5）。

**明確不做的事**：不在編輯過程中打斷、不用倒數計時逼迫、不做假的限時優惠。

**訂閱到期後的行為（呼應 P1）**：

| 行為 | 訂閱中 | 已到期 |
|---|---|---|
| 開啟付費線稿（新的） | ✅ | ❌ |
| 開啟已編輯的作品（含付費線稿） | ✅ | **✅** |
| 繼續編輯、匯出、分享既有作品 | ✅ | **✅** |
| 免費線稿 | ✅ | ✅ |

### 5.5 Settings — 設定

由 Gallery 進入。**只有這幾項**（P3：設定頁應該只有寥寥數項），任何新增都要先回答「它為什麼不能有預設值」。

| 項目 | 內容 |
|---|---|
| **備份** | 說明備份範圍與限制（見 §8）＋ 手動匯出 / 匯入入口 |
| **語言** | 英文 / 繁體中文 / 日文 |
| **關於／客服** | 版本資訊與聯絡入口 |
| **法務** | Privacy Policy、Terms 連結 |

## 6. 內容策略

### v1 圖庫

**50 張線稿**，涵蓋 5–6 個分類：

| 分類 | 說明 |
|---|---|
| 動漫 |  **差異化來源** 有精美細緻的角色與人物（不可與現有IP抄襲與重疊）|
| 曼陀羅 / 幾何 | 高區域數，適合長時間專注 |
| 動物 | 廣泛受眾 |
| 植物 / 花卉 | 適合水彩與噴槍展示 |
| 風景 / 建築 | 中等區域數 |

每個分類需涵蓋三種難度，避免使用者只能在單一難度區間選擇。

### 畫布比例（資產規格）

**只做兩種比例。** 三種以上會讓 Gallery 排版複雜化，換不到對應價值。

| 比例 | runtime 尺寸 | 適用 |
|---|---|---|
| **1:1** | 2048 × 2048 | 通用、曼陀羅、靜物 |
| **4:5** | 1536 × 1920 | 人像、直式風景、動漫角色 |

繪師交付母帶為**長邊 4096**，由 baker 降採樣至 runtime 尺寸——這樣未來調整 runtime 解析度不需要繪師返工。詳見 `architecture.md §9.1`。

社群分享所需的其他比例（9:16 等）由匯出時 letterbox 產生，不影響資產規格。見 §5.3。

### 免費與付費切分

**免費 8–10 張**，選擇標準：

- 涵蓋所有三種難度
- 涵蓋至少 4 個分類
- **至少 2 張是「筆刷價值明顯」的主題**（植物、天空這類需要漸層的）

最後一條特別重要：如果免費圖全是低區域數的簡單圖，使用者會以為這只是個填色遊戲，永遠不會理解訂閱的價值。

**確切數字在 D7（soft launch 觀察期結束）之後依數據收斂**——在那之前 8–10 是區間而非未定，選圖標準先成立即可。

### 更新節奏

**每週 3–5 張，每月 12–20 張。**

訂閱制的續訂理由就是持續有新內容，這個節奏是承諾，不是彈性目標。它同時決定了繪師的產能需求與 baker 管線的自動化程度要求。

## 7. 商業模式

**訂閱制 ＋ 定期更新圖庫。**

| 項目 | 設計 |
|---|---|
| 方案 | 月訂閱、年訂閱（年費折扣約 40%） |
| 試用 | 年訂閱提供 7 天免費試用 |
| 訂閱內容 | 全圖庫解鎖 ＋ 所有新上架線稿 |
| 免費層 | 8–10 張線稿，功能完整（**五支筆刷全開，含縮時影片匯出**） |

**免費層不閹割功能，只限制內容。**

理由：功能閹割會讓使用者誤判產品品質；內容限制才是訂閱制的正確槓桿。使用者必須先體驗到「我塗出了好看的東西」，才會想要更多線稿。

縮時影片匯出**免費層也開放**——它是自然傳播的來源，把它鎖在付費層等於關掉獲客管道，而付費誘因應該來自內容而非功能（同一條原則）。

### 商業模型（待驗證假設）

**以下數字全部是假設，不是目標。** 它們存在的目的是讓「這門生意的下限在哪」有一個可檢驗的答案，而不是精確預測。

| 項目 | 假設值 |
|---|---|
| 月訂閱定價 | `$4.99`（各地區價格層級待定，見附錄 A2） |
| 平台分成後淨收入 | 約 `$3.49` |
| 繪師單張成本 | 約 `$80` |
| 每月新增圖量 | 16 張 |
| **每月固定成本** | **約 `$1,280`** |
| **breakeven 活躍訂閱數** | **約 370 人** |

**這個數字要讀出兩件事**：

1. **下限很低。** 370 個活躍訂閱者是可達成的——代表可以先小規模驗證，不需要賭上全部 50 張圖與整個開發期。這是 `roadmap/SL.md` 存在的直接理由。
2. **瓶頸是獲客，不是內容量。** 如果連 370 都達不到，補圖沒有幫助——商店頁上沒人數你有幾張圖。因此 soft launch 的 **D7 決策點量的是轉換率**，而不是圖庫規模。

## 8. 資料與隱私

| 項目 | 設計 |
|---|---|
| 帳號 | **無**。不註冊、不登入、不收集 email |
| 真相來源 | **使用者的裝置**。雲端只是備份 |
| iOS 備份 | **iCloud Drive ubiquity container**。沿用系統 iCloud，無額外登入提示（見 `architecture.md §11.3`） |
| 手動備份 | 可匯出作品檔到系統檔案 App，並可匯入還原 |
| 分析 | 匿名事件，不含任何可識別個人的資訊 |

### 為什麼要有手動匯出/匯入

系統備份是無感的，但它有兩個使用者無法控制的失效方式：未登入 iCloud、iCloud 空間已滿。

手動匯出是 P1 的**逃生口**——當自動機制失效時，使用者至少有辦法自己保住作品。它也是未來跨平台搬遷的唯一途徑（不需要帳號系統，因此不違反 P4）。

**它列為 v1 Must Have，理由是成本而非重要性改變了。** 備份機制拍板為 iCloud Drive ubiquity container 之後，作品檔本來就存在使用者可見的「檔案」App 目錄裡——手動匯出從「另外實作一套」變成「加一個系統分享面板入口」。P1 的逃生口以近乎零的邊際成本取得，就沒有理由把它留在 Should Have。

在設定頁（§5.5）的「備份」區塊明確說明備份範圍與限制。**只在設定頁說，不在首次啟動時說**——備份的失效情境是嚇人的東西，不該是使用者對這個 App 的第一印象。

### 跨平台不同步

v1 只有 iOS，此限制在 v1 期間不存在。Android 版推出後，兩平台之間**無法自動同步作品**（需要帳號系統，違反 P4），屆時以手動匯出/匯入作為唯一途徑，並在設定頁（§5.5）說明。

## 10. 已知並接受的取捨

**這些不是待辦事項，是已經想過並決定接受的代價。列出來是為了避免日後有人把它們當 bug 修掉。**

| # | 取捨 | 為什麼接受 |
|---|---|---|
| T1 | **訂閱一個月即可永久保留全部內容**——訂閱期間把 50 張全部「開始編輯」，取消後因永久釘選仍可繼續 | P1 的必然代價，無法在不違反 P1 的前提下消除。會這麼做的人本來也不會長期訂閱，且訂閱的價值是**持續的新內容**，這個 exploit 的價值隨時間衰減 |
| T2 | **刻意留白的作品不會觸發完成建議**（因此也看不到完成動畫） | 完成建議必須極度保守（§5.2）。偽陽性打斷創作的代價遠高於漏判 |
| T3 | **麥克筆疊上去之後，改變油漆桶底色不會更新已畫的部分** | 實體直覺一致（紙上畫下去的東西不會因換底色而改變）。替代方案的複雜度高一個量級，見 `architecture.md §4.2` |
| T4 | **Undo 歷史不跨 session 保留** | 持久化 tile 快照的成本與收益不成比例，且使用者隔天已不記得那一筆是什麼 |
| T5 | **雲端備份的筆刷部分是近似還原**（油漆桶部分精確） | 備份有體積上限，不能存 raster。油漆桶是主要玩法且能精確還原 |
| T6 | **v1 只有 iOS** | 單人配置下，Android 需要額外 4–6 週，而核心商業假設在 iOS 上就能驗證 |
