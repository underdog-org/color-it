## 1. 這份文件是什麼

Color It 是一款著色 App。使用者拿到的是**線稿**，他們用油漆桶點擊填色、用筆刷自由塗抹。

因此你交付的不只是一張插畫，而是一組**讓程式能理解「哪裡是哪一塊」的資料**。多出來的工作主要是 `flats.png`（塗り分け／分色圖），這是動畫與漫畫產線的標準交付物。

| | |
|---|---|
| **每張交付** | 4 個 PNG ＋ 1 個 `meta.json` |
| **額外工時** | 相對於單純畫一張線稿，約多 **15–30 分鐘**（`flats` 10–20 分鐘、`reference` 5–10 分鐘） |
| **驗收方式** | 自動化工具（baker）逐項檢查，**不合格會被退回並附上失敗座標**。§7 列出全部檢查項 |
| **原始檔** | `.clip` 等分層原始檔**不需要交付**，但**請自行保管至該作品下架為止**——區域切分日後若需調整，會需要它 |

**最重要的一句話**：`flats.png` 的品質決定整個產品能不能運作。線稿再美，`flats` 有縫隙就會導致使用者填色時「漏色」滿整張畫布。§4.2 與 §6 請仔細看。

## 2. 交付清單與命名

### 2.1 資料夾結構

一張作品一個資料夾，資料夾名就是這張作品的**永久識別碼**：

```
anime-girl-face/
├─ lineart.png
├─ flats.png
├─ reference.png
├─ shade.png        （選配）
└─ meta.json
```

檔名**固定、全小寫**，不得更改。

### 2.2 識別碼命名規則

| 規則 | 說明 |
|---|---|
| 小寫英數 ＋ 連字號 | `anime-girl-face`、`mandala-lotus-01` |
| 純 ASCII，無空格、無中文、無底線 | 它會直接成為伺服器上的檔案路徑 |
| **一經交付即永久不變** | 使用者的作品檔靠它找回自己的線稿。改名 = 產生一張全新的圖，舊作品會全部失效 |

想改顯示名稱時，改 `meta.json` 的 `title`，**識別碼永遠不動**。

## 3. 畫布規格

| 項目 | 規格 |
|---|---|
| **尺寸** | **1:1 → 4096 × 4096**　或　**4:5 → 3072 × 4096**。二選一，沒有第三種 |
| **色彩模式** | RGB，8 bit／channel |
| **色彩描述檔** | **sRGB。導出時不得選 Display P3 或其他描述檔** |
| **對齊** | 四張 PNG 必須**從同一個檔案的不同圖層導出**。分別新建畫布必然錯位，會被退回 |

> **⚠️ 色彩描述檔是最容易犯、也最難察覺的錯。**
> 若 `flats.png` 被色彩管理從 Display P3 轉換到 sRGB，每一個區域色都會被改成鄰近的另一個顏色——結果是憑空多出一堆區域，而且從畫面上完全看不出來。**導出設定裡把描述檔選成 sRGB。**

**為什麼要 4096 這麼大**：App 實際使用的解析度比這個小，由程式自動降採樣產生。要求母帶更大，是為了日後調整解析度時**不需要你重畫**。

## 4. 逐檔規格

### 4.1 `lineart.png` — 線稿

| 項目 | 要求 |
|---|---|
| 格式 | RGBA |
| 抗鋸齒 | **開啟**（正常畫即可） |
| 背景 | **真透明**。導出時**不要**勾選「背景填白」之類的選項 |
| 線條顏色 | 不限純黑。深褐、深藍都可以——線稿在 App 裡是以「色彩增值」疊在最上層，顏色是風格的一部分 |
| 圖層不透明度 | **100%** |

### 4.2 `flats.png` — 分色圖 ★ 最重要

把畫面切成一塊一塊「可以獨立上色的區域」，**每塊填一個純色**。

| 項目 | 要求 |
|---|---|
| 抗鋸齒 | **關閉**。工具屬性面板的「アンチエイリアス／消除鋸齒」必須設為**無** |
| 不透明度 | **筆刷、填充工具、圖層三者都必須是 100%** |
| Alpha | **整張不透明**。不得有任何透明或半透明像素 |
| 覆蓋範圍 | **整張畫布每一個像素都必須有顏色**，包含線稿底下 |
| 漸層 | **完全不允許**。每個區域內部必須是單一數值完全相同的顏色 |

**三條容易誤解的規則：**

**① 沒有「背景」這個概念。** 角色以外的空白處**本身就是一個可上色的區域**，也要填色。使用者確實會想把背景塗成別的顏色。

**② 顏色的作用是「識別」，不是「配色」。** 選色的唯一標準是**你自己肉眼檢查時分得出來**——請用高飽和度、彼此差異大的顏色（螢光綠、洋紅、青、橘）。配色留給 `reference.png`。

**③ 顏色可以重複使用，只要那兩塊不相鄰。** 程式是依「同色 ＋ 相連」來切區域的。所以左手和右手可以都用同一個綠色（它們不相連）；但**臉和脖子如果相連又同色，就會被合併成一塊，使用者只能一次填掉兩塊**。

> **請特別檢查頭髮與背景。** 頭髮常常會延伸到畫面邊緣，如果它和背景用了同色又相連，點一下背景就會連頭髮一起填滿。

**畫在線稿底下。** 在線稿圖層下方新建圖層作業，區域顏色要**填滿到線稿覆蓋的範圍內**——不要只填到線條的內緣，那會留下沒有顏色的縫。

### 4.3 `reference.png` — 建議配色稿

**它是 `flats.png` 的換色版本，不是完成插畫。**

做法：複製 `flats` 圖層 → 用填充工具把每一塊換成你心中真正的建議顏色 → 導出。

| 項目 | 要求 |
|---|---|
| 幾何 | **必須與 `flats.png` 完全一致**——同樣的區域邊界，一個像素都不能差 |
| 抗鋸齒 | **關閉**（同 `flats`） |
| 不透明度 | 整張不透明，全覆蓋（同 `flats`） |
| 內容 | **不含線稿、不含陰影、不含漸層**。每個區域內部單一純色 |
| 顏色 | 這裡才是真正的配色。相鄰區域可以同色（不影響區域切分） |

**為什麼不能直接交完成插畫**：程式需要「這一塊建議塗什麼顏色」這種**逐區一個值**的資料。完成插畫的同一塊裡有幾百種顏色（陰影、漸層、線稿），程式讀不出單一答案。

**這張圖不會被使用者看到**，它只是用來產生 App 裡的建議色盤。所以不需要畫得好看到能當作品——但配色本身要是你真心推薦的那一組。

### 4.4 `shade.png` — 陰影／質感層（選配）

疊在成品上的「色彩增值」層，讓成品有立體感。**這是本產品完成稿精緻度的來源之一，有交比沒交好。**

| 項目 | 要求 |
|---|---|
| 抗鋸齒 | 開啟 |
| 混合模式的預期 | 色彩增值（Multiply） |
| 無陰影處 | **純白 `#FFFFFF`**，或**留透明**——兩者都可以，程式會把透明處自動補成白色 |
| 建議 | 灰階即可。層次不用多，2–3 階就很有效 |

### 4.5 `meta.json`

```json
{
  "id": "anime-girl-face",
  "title": "少女的側臉",
  "category": "anime",
  "notes": "頭髮刻意分成三束"
}
```

| 欄位 | 說明 | 必填 |
|---|---|---|
| `id` | **必須與資料夾名完全一致**。小寫 kebab-case、純 ASCII | ✅ |
| `title` | 內部識別用的名稱，單一語言即可（不會顯示給使用者） | ✅ |
| `category` | **五選一**：`anime` / `mandala` / `animal` / `botanical` / `scenery`。拼錯會被退回 | ✅ |
| `notes` | 給人看的備註，程式忽略 | ⬜ |

檔案必須是合法 JSON（注意逗號與引號），UTF-8 無 BOM。

## 5. Clip Studio Paint 操作流程

```
1. 新建畫布
   4096 × 4096（1:1）或 3072 × 4096（4:5）
   色彩模式 RGB

2. 線稿圖層
   正常畫，抗鋸齒開，圖層不透明度 100%
   → 只顯示此層，導出 lineart.png（PNG，保留透明）

3. flats 圖層（在線稿下方新建）
   工具：「囲って塗る」
     或「自動選択（隙間閉じ ON）」＋「塗りつぶし」
   ★ 工具屬性面板 →「アンチエイリアス」選最左邊（無）
   ★ 不透明度：工具 100%、圖層 100%
   每塊填一個高飽和純色，填滿整張畫布（含背景、含線稿底下）
   → 隱藏其他層，導出 flats.png

4. 檢查縫隙（§6，一定要做）

5. reference 圖層
   複製 flats 圖層 → 逐塊用「塗りつぶし」換成建議配色
   → 導出 reference.png

6. shade 圖層（選配）
   最上層，混合模式「乗算」
   → 導出 shade.png

7. 導出設定
   全部：PNG、sRGB 描述檔、不縮放
```

## 6. 交付前自檢清單

**每一項都要親手確認。** 這份清單就是 baker 會檢查的內容，自己先過一遍可以省下一輪來回。

### 6.1 縫隙檢查法（`flats` 專用，一定要做）

1. 只顯示 `flats` 圖層，隱藏其他所有圖層
2. 在最底下新增一個圖層，整層填成**洋紅 `#FF00FF`**
3. 放大到 100% 全圖掃過一遍

**任何看得到洋紅的地方都是縫隙**，包含：

- 區域之間的細線
- 線稿底下沒填到的部分
- 單獨的一兩個像素（最常見，也最容易漏看）

全部補起來，直到一點洋紅都看不到為止。

> 這一步花你 1 分鐘，但漏掉的話 baker 會退件，來回是一天。

### 6.2 打勾清單

**畫布**

- [ ] 尺寸是 4096×4096 或 3072×4096，沒有其他尺寸
- [ ] 四張 PNG 尺寸完全相同
- [ ] 四張都是從同一個 `.clip` 檔導出的（不是分別新建畫布）
- [ ] 導出時色彩描述檔選 **sRGB**，不是 Display P3

**`lineart.png`**

- [ ] 抗鋸齒**開啟**
- [ ] 背景是**真透明**，導出時沒有勾「背景填白」
- [ ] 圖層不透明度 100%

**`flats.png`**

- [ ] 工具屬性的「アンチエイリアス」設為**無**
- [ ] 筆刷／填充工具的不透明度 **100%**
- [ ] 圖層不透明度 **100%**
- [ ] **整張不透明**，沒有任何透明或半透明像素
- [ ] **每個像素都有顏色**，含背景與線稿底下
- [ ] 每個區域內部是**完全相同的單一顏色**，無漸層
- [ ] 使用**高飽和、彼此差異大**的顏色
- [ ] **已做過洋紅背景縫隙檢查（§6.1），一點洋紅都看不到**
- [ ] **相鄰的區域沒有用相同顏色**——特別檢查頭髮與背景、臉與脖子、衣服與袖子

**`reference.png`**

- [ ] 是 `flats` 的換色版，**區域邊界與 `flats` 完全一致**
- [ ] **不含線稿、不含陰影、不含漸層**
- [ ] 每個區域內部是單一純色
- [ ] 抗鋸齒關閉、整張不透明、全覆蓋

**`shade.png`（若有交）**

- [ ] 無陰影處是純白 `#FFFFFF` 或透明
- [ ] 沒有把線稿或底色畫進去

**`meta.json`**

- [ ] `id` 與資料夾名**完全一致**
- [ ] `category` 是五個允許值之一，拼字正確
- [ ] 是合法 JSON（逗號、引號都對），UTF-8 無 BOM

## 7. baker 會檢查什麼

自動化工具會在收檔時逐項驗證。**不合格會拒收，並附上出問題的座標**，你可以照座標回去修。

| 檢查項 | 失敗代表 | 怎麼修 |
|---|---|---|
| 四張圖尺寸與對齊一致 | 有一張是分別新建畫布畫的 | 從同一個 `.clip` 重新導出 |
| 長邊 4096、比例 1:1 或 4:5 | 畫布尺寸不對 | 重新設定畫布 |
| 色彩描述檔為 sRGB | 導出時選了 Display P3 | 重新導出，描述檔選 sRGB |
| `flats` 無抗鋸齒（顏色數在合理範圍） | 工具的抗鋸齒沒關 | 關掉抗鋸齒重新填色 |
| **無未指派像素（無例外）** | 有縫隙或透明破洞 | 做 §6.1 的洋紅檢查 |
| `reference` 與 `flats` 區域邊界完全一致 | `reference` 不是從 `flats` 複製來的 | 複製 `flats` 圖層重做 |
| `reference` 每區顏色唯一 | `reference` 裡有陰影或漸層 | 每區改成單一純色 |
| `meta.json` 的 `id` 與資料夾名一致、`category` 合法 | 打錯字 | 改 `meta.json` |
| 碎片區域（面積 < 200px） | ⚠️ 警告，不一定是錯 | 確認那些小塊是刻意的（例如亮點），不是雜點 |
| 區域數過多或過少 | ⚠️ 警告 | 見 §8 的區域數建議 |

## 8. 常見問題

**Q：一張圖大概要切幾個區域？**

| 難度 | 區域數 | 感覺 |
|---|---|---|
| 輕鬆 | ≤ 60 | 10–15 分鐘可完成 |
| 適中 | 61–200 | 20–30 分鐘 |
| 專注 | > 200 | 30 分鐘以上，適合曼陀羅這類 |

難度由程式依區域數自動判定，你不需要指定。但接稿時我們會說明這張要哪一種難度。

**Q：相鄰的兩塊可以用同一個顏色嗎？**

不行。它們會被合併成一塊，使用者只能一次填掉兩塊。不相鄰的兩塊則完全沒問題，可以放心重複用色。

**Q：眼睛的高光、髮絲這種很小的細節要不要分成獨立區域？**

小於 200px（約 14×14 像素）的區域會被標記為警告。刻意的高光沒問題，但要避免無意義的碎點——使用者用手指很難點到那麼小的區域。

**Q：線稿底下要填什麼顏色？**

填**兩側任一邊的區域色**都可以，程式會處理。重點只有一個：**不能留空**。

**Q：`flats` 的顏色會不會被使用者看到？**

不會。它純粹是給程式讀的。使用者看到的建議色來自 `reference.png`。

**Q：交完之後想改配色可以嗎？**

可以，而且不影響既有作品——只要重交 `reference.png` 就好。

**但 `flats.png` 一旦上線就不能改**。改動區域切分會讓已經在畫這張圖的使用者的作品失效。所以 `flats` 請在交付前確認到位。

**Q：`shade.png` 一定要交嗎？**

不是必要，但強烈建議。它是成品好不好看的關鍵之一。

**Q：可以用 Procreate 畫嗎？**

`lineart` 和 `shade` 可以。**`flats` 不行**——Procreate 的填色與筆刷強制抗鋸齒，沒有硬邊模式，做不出合格的分色圖。`flats` 請用 Clip Studio Paint 或 Photoshop。
