# Colorlull — 素材交付規格

> 給繪師的交付規格。
> 狀態：v2.0（2026-08-03）——交付從「線稿＋分色圖＋配色稿」改為「**線稿＋色標圖**」。
> 區域不再由你填的顏色決定，改由**線稿的封閉區**決定（設計理由見 [baker-seeds.md](./baker-seeds.md)）。
> v1.1 的 `flats.png` 與 `reference.png` 已廢止，不必再交。
> 相關文件：[architecture.md §9](../architecture.md)｜[prd.md](../prd.md)

---

## 0. 一頁摘要（可整段複製進 JD）

> **Colorlull 線稿素材外包｜交付規格摘要**
>
> 一張作品交 **2 個必交 PNG**（`lineart.png` / `seeds.png`）＋ 1 個選配（`shade.png`）＋ 1 個 `meta.json`。
> 畫布 **4096×4096（1:1）或 3072×4096（3:4）**，sRGB，四張從同一個檔案的不同圖層導出。
>
> `lineart.png`：正常畫線稿，抗鋸齒開，透明底。**唯一的額外要求是線要封閉**——每一塊要能被線圍起來。
>
> `seeds.png`：新圖層，在每一個封閉區裡點**一個**色點，**點的顏色就是你建議這一塊塗的顏色**。
> 抗鋸齒開著沒關係、形狀不限、相鄰的點同色也沒關係。直徑約 16px 以上即可。
>
> **一個封閉區一個點——不是一個顏色一個點。** 線稿把一片顏色切成幾塊，就要點幾個點。
>
> 相對於單純畫一張線稿，額外工時約 **5–10 分鐘**。
> 交付由自動化工具驗收，不合格會退回並附上失敗座標與三張標好問題的圖。

## 1. 這份文件是什麼

Colorlull 是一款著色 App。使用者拿到的是**線稿**，他們用油漆桶點擊填色、用筆刷自由塗抹。

所以你交付的不只是一張插畫，而是一組**讓程式知道「哪裡是哪一塊」的資料**。這件事由兩件東西共同決定：

- **線稿決定區域的邊界**——程式在線稿的封閉區裡做填充，跟你在 PS／CSP 裡用油漆桶點一下是同一回事
- **色標決定哪些區域存在、以及每一塊建議塗什麼顏色**

| | |
|---|---|
| **每張交付** | **2 個必交 PNG**（`lineart` / `seeds`）＋ **1 個選配**（`shade`）＋ 1 個 `meta.json` |
| **額外工時** | 相對於單純畫一張線稿，約多 **5–10 分鐘** |
| **驗收方式** | 自動化工具（baker）逐項檢查，**不合格會被退回並附上失敗座標與三張標好問題的圖**。§7 列出全部檢查項 |
| **原始檔** | `.clip` 等分層原始檔**不交付、也不會進我們的版控**。**請自行保管至該作品下架為止** |

> **⚠️ 關於原始檔，有一件事必須在合作前講明。**
> 我們只保存你導出的 PNG，不保存分層檔。日後若需要調整區域切分（某塊要再拆細、兩塊要合併），
> 那是**改線稿**——請務必保留 `.clip`。

**最重要的一句話**：

> **一個封閉區一個點——不是一個顏色一個點。**

一片白色被線稿切成 8 塊，就要點 8 個白點。實測一張典型作品有 62 個封閉區、但只用了 7 個顏色——照「一個顏色點一個」的直覺去點，會有 55 塊被判定成「漏點」而整張退回。

## 2. 交付清單與命名

### 2.1 資料夾結構

一張作品一個資料夾，資料夾名就是這張作品的**永久識別碼**：

```
anime-girl-face/
├─ lineart.png
├─ seeds.png
├─ shade.png        （選配）
└─ meta.json
```

檔名**固定、全小寫**，不得更改。

### 2.2 識別碼命名規則

| 規則 | 說明 |
|---|---|
| 小寫英數 ＋ 連字號 | `anime-girl-face`、`mandala-lotus-01` |
| 純 ASCII，無空格、無中文、無底線 | 它會直接成為伺服器上的檔案路徑 |
| **一經交付即永久不變** | 使用者的作品檔靠它找回自己的線稿。改名 = 產生一張全新的圖，舊作品會全部失效 |

想改顯示名稱時，改 `meta.json` 的 `title`，**識別碼永遠不動**。

## 3. 畫布規格

| 項目 | 規格 |
|---|---|
| **尺寸** | **1:1 → 4096 × 4096**　或　**3:4 → 3072 × 4096**。二選一，沒有第三種 |
| **色彩模式** | RGB，8 bit／channel |
| **色彩描述檔** | **sRGB**。沒有嵌任何描述檔也算通過。判準是描述檔的**內容**（primaries／TRC），不是它的名稱 |
| **對齊** | 各張 PNG 必須**從同一個檔案的不同圖層導出**。分別新建畫布必然錯位，會被退回 |

**為什麼要 4096 這麼大**：App 實際使用的解析度比這個小，由程式自動降採樣產生。要求母帶更大，是為了日後調整解析度時**不需要你重畫**。

## 4. 逐檔規格

### 4.1 `lineart.png` — 線稿 ★ 最重要

| 項目 | 要求 |
|---|---|
| 格式 | RGBA |
| 抗鋸齒 | **開啟**（正常畫即可） |
| 背景 | **真透明**。導出時**不要**勾選「背景填白」之類的選項 |
| 線條顏色 | 不限純黑。深褐、深藍都可以——線稿在 App 裡是以「色彩增值」疊在最上層，顏色是風格的一部分 |
| 圖層不透明度 | **100%** |
| **封閉性** | **每一塊可上色的區域都要被線圍起來**。見下 |

**封閉性是這份契約裡唯一真正的技術要求。**

程式是在線稿的封閉區裡做填充的。線如果有缺口，兩塊會連成一塊——使用者點一下就會把兩塊一起填掉，而且顏色會從缺口「漏」出去。

- 線與線的**交叉處**最容易留縫：兩筆看起來接上了，放大到 100% 才發現差一兩個像素
- 你在 CSP／PS 裡用**油漆桶點一下**就能驗證：填料漏出去的地方就是缺口
- **裝飾性的開放筆畫沒問題**——草叢的短撇、金屬的反光線、頭髮的內部線條，這些不圍成封閉區的線不會造成任何問題，照畫

線稿有缺口時，baker 會回報 `seed-collision`，並附上**兩個色標的座標**：你要補的線就在這兩點之間。

### 4.2 `seeds.png` — 色標圖

在線稿上方（或下方，不影響）新建一個圖層，**在每一個你希望能單獨上色的區域裡，點一個色點**。

| 項目 | 要求 |
|---|---|
| 格式 | RGBA，尺寸同 `lineart` |
| 背景 | **透明**。除了色點以外不要有任何東西 |
| 內容 | 每個要獨立上色的區域裡點**一個**色點 |
| 色點形狀 | **不限**。圓的方的隨手一點都可以 |
| 色點大小 | 直徑約 **16px 以上**（母帶 4096 級上這只是隨手一點的大小） |
| 抗鋸齒 | **開著沒關係**。程式只讀完全不透明的那些像素 |
| **顏色** | **就是建議色**——你希望 App 建議使用者塗在這一塊的那個顏色 |
| 相鄰同色 | **允許**。區域由線稿決定，不由顏色決定 |
| 色點位置 | 點在區域**裡面**，不要壓在線上；凹形區域請點在肚子裡，不要點在缺口處 |

**三件事你不用再操心了**（這些是 v1.1 的規則，已廢止）：

- 不用關抗鋸齒
- 不用填滿整張畫布、不用管線稿底下
- 不用避免相鄰同色，也沒有保留色

**為什麼色點的顏色一色兩用**：它同時是「這裡有一個區域」的標記與「這一塊建議塗什麼」的答案。代價是你在自己的工具裡看不到整體配色效果——所以我們會把 `reference-preview.png`（用你的建議色渲染的整張圖）附回給你，見 §7。

### 4.3 `shade.png` — 陰影／質感層（選配）

疊在成品上的「色彩增值」層，讓成品有立體感。**這是本產品完成稿精緻度的來源之一，有交比沒交好。**

| 項目 | 要求 |
|---|---|
| 抗鋸齒 | **開啟**。硬邊的陰影會在成品上顯得廉價 |
| 混合模式的預期 | 色彩增值（Multiply） |
| 無陰影處 | **純白 `#FFFFFF`**，或**留透明**——兩者都可以，程式會把透明處自動補成白色 |
| 內容 | **不得把線稿或底色畫進去**。判準：不得有 luma < 60 的像素（那個暗度只可能是線稿） |
| 建議 | 灰階即可。層次不用多，2–3 階就很有效 |

### 4.4 `meta.json`

```json
{
  "id": "anime-girl-face",
  "title": "少女的側臉",
  "category": "anime",
  "notes": "頭髮刻意分成三束"
}
```

| 欄位 | 說明 | 必填 |
|---|---|---|
| `id` | **必須與資料夾名完全一致**。小寫 kebab-case、純 ASCII | ✅ |
| `title` | 內部識別用的名稱，單一語言即可（不會顯示給使用者） | ✅ |
| `category` | **六選一**：`anime` / `cartoon` / `mandala` / `animal` / `botanical` / `scenery`。拼錯會被退回 | ✅ |
| `notes` | 給人看的備註，程式忽略 | ⬜ |

檔案必須是合法 JSON（注意逗號與引號），UTF-8 無 BOM。

## 5. 操作流程

```
1. 新建畫布
   4096 × 4096（1:1）或 3072 × 4096（3:4），RGB

2. 線稿圖層
   正常畫，抗鋸齒開，圖層不透明度 100%
   ★ 每一塊要被線圍起來（用油漆桶點一下自檢，見 §6）
   → 只顯示此層，導出 lineart.png（PNG，保留透明）

3. seeds 圖層（新建，背景透明）
   每個封閉區點一個色點，顏色 = 你的建議色
   ★ 一個封閉區一個點，不是一個顏色一個點
   → 只顯示此層，導出 seeds.png

4. shade 圖層（選配）
   最上層，混合模式「乗算」
   → 導出 shade.png

導出設定：全部 PNG、sRGB、不縮放
```

**工具不限。** 沒有任何一步需要關抗鋸齒或硬邊填色，所以 Procreate、Photoshop、Clip Studio Paint 都可以完成全部交付。（v1.1 的 `flats.png` 需要硬邊填色，那是 Procreate 做不到的——這個限制已經沒有了。）

## 6. 交付前自檢清單

**線稿封閉性（唯一需要花時間的一項）**

- [ ] 在線稿下方新建一個圖層，用**油漆桶**逐塊點過去
- [ ] 沒有任何一次填色漏到隔壁區
- [ ] 交叉處、線的端點特別確認過
- [ ] 檢查完把這個測試圖層**刪掉或隱藏**，不要導出到交付檔裡

**打勾清單**

- [ ] 尺寸是 4096×4096 或 3072×4096
- [ ] 各張 PNG 尺寸完全相同，且從同一個檔案導出
- [ ] 導出色彩描述檔是 sRGB
- [ ] `lineart` 背景**真透明**，抗鋸齒開，圖層不透明度 100%
- [ ] `seeds` 背景**透明**，除了色點沒有別的東西
- [ ] **每一個封閉區都有一個點**——含背景、含每一小塊，數量通常遠多於你用的顏色數
- [ ] 沒有任何一個封閉區裡有**兩個**點
- [ ] 色點都在區域裡面，沒有壓在線上
- [ ] 色點直徑都在 16px 以上
- [ ] `shade`（若有交）無陰影處是白或透明，畫面上沒有接近全黑的地方
- [ ] `meta.json` 的 `id` 與資料夾名一致、`category` 拼字正確、是合法 JSON

## 7. baker 會檢查什麼

自動化工具會在收檔時逐項驗證。**不合格會拒收，並附上出問題的座標。**

| 檢查項（代碼） | 失敗代表 | 怎麼修 |
|---|---|---|
| `seed-collision` | **線稿有缺口**：兩個色標落進同一個封閉區 | 在回報的**兩點之間**補線 |
| `orphan-area` | **漏點了**：有封閉區沒有色標 | 在回報的座標補一個點 |
| `seed-too-small` | 色點太小，取不出可靠的顏色 | 把點畫大一點（直徑 16px 以上） |
| `seed-on-line` | 色點壓在線上 | 把點移進封閉區裡面 |
| `line-coverage` | ⚠️ 警告：整張圖太多像素被判成線 | 通常是 `lineart` 交成**白底**而不是透明底 |
| `size-mismatch` / `canvas-size` | 尺寸不一致或畫布尺寸不對 | 從同一個檔案重新導出 |
| `color-space` | 色彩描述檔不是 sRGB | 重新導出，描述檔選 sRGB |
| `shade-too-dark` | 線稿或底色被畫進 `shade` | 只留陰影本身 |
| `meta-id-mismatch` / `meta-bad-category` | `meta.json` 打錯字 | 改 `meta.json` |
| `tiny-region` | ⚠️ 警告：碎片區域（母帶面積 < 800px） | 確認那些小塊是刻意的（例如亮點），不是雜點 |
| `region-count-range` | ⚠️ 警告：區域數過多或過少 | 見 §8 的區域數建議 |

**所有問題會一次全部回報**，不會修一條退一次。

### 退件時你會收到三張圖

比起一串座標，直接看圖快得多：

| 檔 | 怎麼看 |
|---|---|
| `preview.png` | 每個區域塗上高對比的隨機色。**兩塊該分開卻是同一個顏色 → 線稿在它們之間有缺口**；**白色的區塊 → 那裡沒有色標** |
| `seeds-overlay.png` | 淡色線稿 ＋ 你點的每一個色標。紅線連起來的兩點 = 撞在一起（要補線）；黃框圈起來的 = 漏點 |
| `reference-preview.png` | 用你的建議色渲染的整張圖。**這是你在自己的工具裡看不到的整體配色效果**，就算通過驗收也值得看一眼 |

> **碎片門檻為什麼是 800 而不是 200。**
> baker 的檢查跑在**輸出**解析度（母帶的一半，見 `architecture.md §9.3`），門檻是輸出的 200px。
> 面積隨邊長平方縮，母帶 4096 → 輸出 2048 是 4 倍差——**你在母帶上該盯的數字是 800px（約 28×28）**。

## 8. 常見問題

**Q：為什麼我要點 62 個點，只用了 7 個顏色？**

因為區域是線稿切出來的，不是顏色切出來的。一把劍被交叉的線切成 8 段，那就是 8 個區域，使用者可以分別上色——這對著色體驗是加分，代價是你要點 8 個點。

判斷方式很簡單：**你用油漆桶點一下會填滿的範圍，就是一個區域，就要有一個點。**

**Q：線稿有個小缺口會怎樣？**

兩塊會連成一塊。如果那兩塊你都點了色標，baker 會回報 `seed-collision` 並退件，附上那兩個點的座標——補一筆線就好。

如果缺口小到只圍出幾百像素的碎塊，程式會自動把它併進最大的鄰區，不會退件。

**Q：一張圖大概要切幾個區域？**

| 難度 | 區域數 | 感覺 |
|---|---|---|
| 輕鬆 | ≤ 60 | 10–15 分鐘可完成 |
| 適中 | 61–200 | 20–30 分鐘 |
| 專注 | > 200 | 30 分鐘以上，適合曼陀羅這類 |

難度由程式依區域數自動判定，你不需要指定。但接稿時我們會說明這張要哪一種難度。

> 這張表的數字是全專案的唯一依據——`architecture.md §9.4` 與 `roadmap/M1.md` 都只是引用它。若要調整門檻，三處必須一起改。

**Q：相鄰的兩塊可以點同一個顏色嗎？**

可以。區域由線稿決定，顏色只是建議色。臉和脖子都點膚色完全沒問題——v1.1 的「相鄰不可同色」限制已經沒有了。

**Q：色點會被使用者看到嗎？**

不會。使用者看到的是「建議色」色盤，也就是你點的那些顏色，但色點本身不會出現在畫面上。

**Q：交完之後想改配色可以嗎？**

可以，重交 `seeds.png` 就好，不影響既有作品——只要你**沒有改動色點的位置與數量**。

**但改動線稿或區域切分會讓已經在畫這張圖的使用者的作品失效**，所以線稿請在交付前確認到位。

**Q：眼睛的高光、髮絲這種很小的細節要不要獨立成一區？**

母帶上小於 800px（約 28×28 像素）的區域會被標記為警告。刻意的高光沒問題，但要避免無意義的碎點——使用者用手指很難點到那麼小的區域。

**Q：可以用 Procreate 畫嗎？**

可以，全部都可以。這一版的交付沒有任何一步需要硬邊填色。
