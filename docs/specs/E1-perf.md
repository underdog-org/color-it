## 1. 測試裝置與量測條件

| 檔位 | 機型 | 為什麼是它 |
|---|---|---|
| 高階 | ProMotion 的 iPhone（120 Hz） | 上限。`preferredFrameRateRange` 與 `maximumDrawableCount` 的效果只在這裡看得出來 |
| 中階 | 60 Hz、A13–A15 世代 | 真實下限。一格 16.7 ms，latency 絕對值明顯較差 |
| Android | 低階機一台（D2 專用） | `checkpoints.md` 的採購項，**W3 前**要到位 |

**每次量測前的固定條件**（寫進 `perf-baseline.md` 的表頭，不靠記憶）：
電量 > 50% 且未充電、飛航模式、重開 App、關閉低耗電模式、螢幕亮度固定 50%。

熱節流會讓第二輪比第一輪差 20% 以上。**連續量測之間靜置 5 分鐘。**

## 2. motion-to-photon

240 fps 以上（iPhone 內建慢動作即可，另一台手機拍受測機）。畫面裡必須同時有**手指**
與**螢幕**，且螢幕上有可辨識的筆跡前緣。固定機位與距離，受測機平放，
光源不在正上方（反光會蓋掉筆跡）。

```
latency = (f_paint - f_touch) / 240 × 1000 ms
  f_touch = 手指開始移動的第一格
  f_paint = 筆跡前緣開始跟上的第一格
```

**每次量 5 趟取中位數**，不取最小值——最小值是運氣，使用者感受到的是分佈。

三種動作都要：**慢速直線**（基準，預測貢獻最小）、**快速來回**（預測誤差最容易看見）、
**從靜止起筆**（量 `touchesBegan` 到第一次 render 那段，`E1-input §3.1`）。

### 2.1 兩根調節桿

不達標時**依序**動這兩個，一次一個，各自重量一輪：

1. `maximumDrawableCount`：2 vs 3（`E1-wgpu §3.1`）
2. 輸入批次時機（`E1-input §3.1`）

兩根都調完仍不達標，才觸發 `architecture.md §14 R1` 的退路評估。
**不要跳過這一步直接懷疑 wgpu**——那是 D3 最貴的誤判。

## 3. frame time p99 與 D2

**取數**：Instruments 的 Metal System Trace，連續塗抹 30 秒，取 GPU frame 的 **p99**
而非平均——平均會被大量閒置 frame 拉低到毫無意義。同一份 trace 順便取 Pass 1
與 Pass 3 的分項耗時（`E1-composite §7` 說「先量這個 pass 再談優化」，這裡就是那個量）。

**D2 Android spike（1 天，W6）**：

```
1. wgpu hello-triangle 跑起來 → 確認 backend（Vulkan 還是 GLES）
2. 建 R16Uint texture ＋ textureLoad → 逐值 readback 比對
3. 若 2 失敗：試 RG8 打包（低／高位兩通道）→ 同樣逐值比對
```

**D2 的產出是「資產格式安不安全」，不是效能數字。** 第 2 步過了就結案，
不需要在 Android 上跑完整 App。

## 4. 必答：E1 版的記憶體劇本

`architecture.md §13.1` 的劇本含「undo pool 塞滿」，**E1 沒有 undo pool**——
照原劇本量會得到一個好看但無意義的數字。而 `E1-wgpu §4.2` 又指出預算表**漏了兩筆**。

| 項目 | 預估 | 來源 |
|---|---|---|
| 文件級貼圖 | 64 MB | `architecture.md §4.1.1` |
| swapchain drawable | 24–36 MB | `E1-wgpu §4.2`，**預算表未列** |
| `region_ids` CPU 副本 | 8 MB | `E1-wgpu §5.1`，**預算表未列** |
| **E1 可量到的合計** | **96–108 MB** | |

**D4 的判定改成三步**，不是拿 96–108 直接比 145：

1. 量到真機實際值，**回填 `§4.1.1` 缺的兩列**
2. 加上 E3 undo pool 的估算值（`§4.1.1` 已有該列，照用）
3. **對修正後的總額判定**。超標 → 此時調畫布解析度（繪師尚未量產，代價最低）

第 1 步即使總額沒超標也必須做——**預算表漏兩筆是已知事實，不會因為 E1 沒超標就消失**。

**劇本**：Xcode Memory Report 取 peak。開最大畫布 → 連續塗抹 30 秒 → 連填 20 個區域
（動畫全開）→ 切出 App 再切回（順便驗 `detach` 不釋放資源，`E1-wgpu §9`）。

## 5. D4：Mask Mode A／B

**開關做法**：Debug 選單一個 toggle，直接呼叫 `RenderContext::set_mask`
（一次 `write_buffer`，不重建 pipeline——`E1-wgpu §7.1`）。不做成正式 UI，
D4 之後留一個會被誤觸。

**比較劇本**（同一位受試者兩種都試，順序隨機）：

1. 填一個區域後**故意畫出界**——A 擋住，B 塗到隔壁
2. 橫跨多區的長筆畫——A 斷成一段一段，B 連續
3. 塗細長區域（睫毛、髮絲）——A 的保護在這裡最有價值

**產出是產品決策**：寫回 `prd.md §4.1`，同時結案附錄 A6；E2 的「Mask Mode 參數化」依此定案。

## 6. D3：主觀手感盲測

**RS4 的紅線：不得自評。**

| 條款 | 內容 |
|---|---|
| 受試者 | 三人以上，非本專案參與者 |
| 器材 | **手指**。有 Pencil 也要先用手指跑完一輪 |
| 不說什麼 | 不說是自製 App、不說在測 latency、不說有哪些參數 |
| 問什麼 | 「畫起來跟不跟手？」開放作答，追問「哪裡怪」 |
| 對照組 | 同一台機器上的一款市售繪圖 App，順序隨機 |
| 通過條件 | 三人皆答「跟手」，且**沒有人主動提到延遲** |

「沒有人主動提到延遲」比「答跟手」更硬——被問到時人傾向給正面回答，主動抱怨不會憑空發生。

不通過 → 先查 present 路徑（§2.1 的兩根桿），再觸發 `architecture.md §14 R1`。
**超過 8 週時間盒仍未通過 D3 → 停止往下做**（`E1.md`）。

## 7. 調校項總表

散在五份 spec 的初值集中在這裡。**調完要記進 `perf-baseline.md`**，
否則下次沒人知道現在的值是量出來的還是猜的。

| 項目 | 初值 | 出處 | 怎麼判斷調好了 |
|---|---|---|---|
| One-Euro 位置 `min_cutoff`／`beta`／`d_cutoff` | 1.0／0.05／1.0 | `E1-stroke §4.1` | 慢速直線不抖，快速轉向不拖尾 |
| One-Euro radius 同上三項 | 0.5／0.0／1.0 | `E1-stroke §4.1` | 定點加壓時筆寬平順，不跳 |
| `R_EPS` | 4.0 點 | `E1-stroke §5` | 起筆瞬間的筆寬不是最細或最粗 |
| `FILL_EDGE` | 24 px | `E1-composite §5` | 前緣柔和但看得出是擴散 |
| 動畫時長 | 180 ms ease-out | `E1-bucket §7.3` | 感覺得到但不必等 |
| `maximumDrawableCount` | 2 | `E1-wgpu §3.1` | §2 的 latency 中位數 |
| `MAX_DABS_PER_DRAW` | 4096 | `E1-stroke §7` | 快速長筆畫不斷線（正確性，不是手感） |

**細長區域的追趕感**：圓形擴散會先填滿寬處、細處慢慢追上，看起來像卡住。
找一張含細長區域的實際線稿，填色錄影逐格看。**判準先寫在這裡，避免事後找理由**——
若 180 ms 內細處落後寬處**超過 60 ms 可辨識**，就值得評估改測地距離擴散
（`architecture.md §4.5`）。那是 E2 的事，**E1 只出結論，不改實作**。

## 8. `docs/perf-baseline.md` 的版型

一個裝置一節，每次量測**追加一列而非覆寫**——歷史值就是回歸偵測。

```markdown

## 調校記錄          （§7 的表，每次調完追加）
```

## 9. 已否決

| 做法 | 為何不 |
|---|---|
| motion-to-photon 取最小值 | 最小值是運氣，使用者感受到的是分佈（§2） |
| frame time 取平均 | 被閒置 frame 拉低到無意義（§3） |
| 拿 E1 的裸記憶體數字比 145 MB | 預算表漏兩筆、E1 沒有 undo pool，兩邊都不對（§4） |
| 因為沒超標就不補預算表 | 漏兩筆是已知事實，不會自動消失（§4） |
| Mask 切換做成正式 UI | D4 之後會被誤觸（§5） |
| 自評手感、只用觸控筆測 | RS4 的紅線 ＋ `E1.md` 驗收明文（§6） |
| 一次調多個參數 | 效果混在一起，分不出是誰的功勞（§2.1） |
| 在 Android 上跑完整 App | D2 保護的是資產格式，不是 Android 效能（§3） |
