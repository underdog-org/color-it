## 量測條件

每次量測前逐條確認，不靠記憶：

- [ ] 電量 > 50% 且**未充電**
- [ ] 飛航模式
- [ ] 重開 App
- [ ] 關閉低耗電模式
- [ ] 螢幕亮度固定 50%
- [ ] 距離上一輪量測已靜置 **5 分鐘**（熱節流會讓第二輪差 20% 以上）

`m2p` 欄一律填**5 趟的中位數**，不是最小值——最小值是運氣，使用者感受到的是分佈。

## motion-to-photon（m2p）

240 fps 以上（iPhone 內建慢動作即可，另一台手機拍受測機）。畫面裡必須同時有**手指**與**螢幕**，
且螢幕上有可辨識的筆跡前緣。固定機位與距離，受測機平放，光源不在正上方（反光會蓋掉筆跡）。

```
latency = (f_paint - f_touch) / 240 × 1000 ms
  f_touch = 手指開始移動的第一格
  f_paint = 筆跡前緣開始跟上的第一格
```

三種動作都要：**慢速直線**（基準，預測貢獻最小）、**快速來回**（預測誤差最容易看見）、
**從靜止起筆**（量 `touchesBegan` 到第一次 render 那段）。

**兩根調節桿**，不達標時**依序**動這兩個，一次一個，各自重量一輪：
1. `maximumDrawableCount`：2 vs 3
2. 輸入批次時機

兩根都調完仍不達標，才觸發 `architecture.md §14 R1` 的退路評估。
**不要跳過這一步直接懷疑 wgpu**——那是 D3 最貴的誤判。

## frame time p99

取數：Instruments 的 Metal System Trace，連續塗抹 30 秒，取 GPU frame 的 **p99** 而非平均——
平均會被大量閒置 frame 拉低到毫無意義。同一份 trace 順便取 Pass 1 與 Pass 3 的分項耗時
（先量這個 pass 再談優化）。

## 對帳：`architecture.md §4.1.1`

三步，缺一不可。**第 1 步即使總額沒超標也必須做**——預算表漏兩筆是已知事實。

| 步驟 | 內容 | 數字 |
|---|---|---|
| 1 | 實測 swapchain drawable，回填 `§4.1.1` | 待實測（估 24–36 MB） |
| 1 | 實測 `region_ids` CPU 副本，回填 `§4.1.1` | 待實測（估 8 MB） |
| 2 | 加上 E3 undo pool 的估算值（`§4.1.1` 已有該列） | 64 MB |
| 3 | **對修正後的總額判定**。超標 → 此時調畫布解析度 | 待判定 |

E1 的劇本：開最大畫布 → 連續塗抹 30 秒 → 連填 20 個區域（動畫全開）→ 切出 App 再切回
（順便驗 `detach` 不釋放資源）。**E1 沒有 undo pool**，不照 `§13.1` 的原劇本量。

## D2／D3／D4 劇本

**D2 · R16Uint 在低階 Android**（1 天 spike，產出是「資產格式安不安全」，不是效能數字）：

```
1. wgpu hello-triangle 跑起來 → 確認 backend（Vulkan 還是 GLES）
2. 建 R16Uint texture ＋ textureLoad → 逐值 readback 比對
3. 若 2 失敗：試 RG8 打包（低／高位兩通道）→ 同樣逐值比對
```

第 2 步過了就結案，不需要在 Android 上跑完整 App。

**D4 · Mask Mode A／B 比較**（同一位受試者兩種都試，順序隨機；開關在 `CanvasScreen` 的
`MaskModeToggle`，Debug 限定）：

1. 填一個區域後**故意畫出界**——A 擋住，B 塗到隔壁
2. 橫跨多區的長筆畫——A 斷成一段一段，B 連續
3. 塗細長區域（睫毛、髮絲）——A 的保護在這裡最有價值

**產出是產品決策**：寫回 `prd.md §4.1`，同時結案附錄 A6。

**D3 · 主觀手感盲測**（RS4 的紅線：不得自評）：

| 條款 | 內容 |
|---|---|
| 受試者 | 三人以上，非本專案參與者 |
| 器材 | **手指**。有 Pencil 也要先用手指跑完一輪 |
| 不說什麼 | 不說是自製 App、不說在測 latency、不說有哪些參數 |
| 問什麼 | 「畫起來跟不跟手？」開放作答，追問「哪裡怪」 |
| 對照組 | 同一台機器上的一款市售繪圖 App，順序隨機 |
| 通過條件 | 三人皆答「跟手」，且**沒有人主動提到延遲** |

「沒有人主動提到延遲」比「答跟手」更硬——被問到時人傾向給正面回答，主動抱怨不會憑空發生。
不通過 → 先查 m2p 的兩根調節桿，再觸發 `architecture.md §14 R1`。
